## 0. 这是什么（30 秒看懂）

> ⚠️ **门禁规则**：在改动任何 **Response headers / 返回 HTML / 依赖平台行为的代码** 之前，
> **先查这张卡**。不要像 #35 那样在 `Content-Type` 上反复返工 4 轮——
> 根因是 **Supabase 默认域名禁止 Edge Function 返回 HTML**（平台行为），本地测试永远测不出。

**本地 mock 测试 PASS ≠ 部署后真实行为正确。**
本地测试只验证逻辑，**覆盖不了 Supabase 网关的 rewrite 行为**。
涉及 UI/HTML/headers 的改动，部署后必须走 `docs/deploy_verification_checklist_v1.0.md` 的浏览器级验证。

## 1. 核心约束（来自 #35 复盘，最高频）

### C1 — 默认域名禁止 Edge Function 返回 HTML ⛔

| 项 | 内容 |
|---|---|
| **现象** | 确认页在浏览器显示 HTML 源码；F12 看到 `Content-Type: text/plain`（期望 `text/html`） |
| **根因** | Supabase 官方：默认 `*.supabase.co` 域名下，GET 返回 `text/html` 会被网关**强制 rewrite 为 `text/plain`**；只有配置**自定义域名**后才能直接返回 HTML |
| **错误修法** | 改 `Headers` 实例 / 把 body 转 `Uint8Array` bytes / 加 `<meta charset>` —— **全部无效**，因为网关在更外层改写 |
| **正确架构** | **外部静态页 + 302 redirect**：函数 GET 只校验 token → 302 跳 GitHub Pages/Netlify 静态页渲染 UI → 表单 POST 回函数执行 |
| **最小预检** | 动手前问自己：「这函数要在默认域名下直接返回 HTML 吗？」→ 是，就别走直出，改 302 架构 |
| **参考** | `SOP_supabase_data_upload.md` §9.1–§9.2；`docs/approval.html`（本项目的静态确认页范例） |

## 2. 其他已知平台 / 部署约束（速查，避免踩同类坑）

| 编号 | 约束 | 正确做法 | 来源 |
|---|---|---|---|
| C2 | 环境变量**禁用 `SUPABASE_` 前缀**（CLI v2.109+ 护栏） | 改用 `PROJECT_` 前缀（如 `PROJECT_APPROVAL_SECRET`），启动期 `checkEnv()` 缺失即 500 | 长期经验 |
| C3 | 外部 webhook / 邮件点击**不发 JWT** | 部署必须 `--no-verify-jwt`（或 MCP `verify_jwt: false`） | 长期经验 |
| C4 | Edge Function 运行时**动态 import 外部 CDN 不可靠**（esm.sh/jsdelivr 等可能 `Module not found`） | 关键依赖 vendor 到函数目录（如 `./xlsx.mjs`）用静态 `import` | 长期经验 |
| C5 | 静态页托管在 GitHub Pages 时，主分支是 **`master`**（不是 `main`） | Pages Source 选 `master` + `/docs`；改完 `git push` 等 1–3 分钟重新部署 | #35 实战 |
| C6 | `Deno.serve` 对 string body 会自动推断 `text/plain` | 若确需函数内返回非 HTML 文本，显式传 `headers`；但 HTML 仍受 C1 限制 | #35 实战 |

> 说明：C2–C6 是部署/代码层约束，不属"网关 rewrite"，但同属「平台行为，本地测不出」，一并列出便于开发前扫一遍。

## 3. 预检门禁流程（每次涉及 UI/HTML/headers 改动必走）

```
[动手改代码前]
  1. 查这张卡 §1–§2，确认要做的改动是否被平台支持
       ├─ 要函数直出 HTML？ → 受 C1 限制 → 改 302 架构（不要调 headers）
       └─ 其他约束命中？ → 按对应「正确做法」调整
  2. 写代码 + 本地集成测试（仅验证逻辑；在测试文件顶部标注「不覆盖网关行为」）
       ↓
[部署后]
  3. 必须走 docs/deploy_verification_checklist_v1.0.md §3.3 浏览器真实渲染检查
     → 截图 + Content-Type=text/html + 含 DOM 才算 PASS
```

**任一项不通过 → 回到第 1 步排查架构，不要只调 headers。**

## 4. 在代码 / 测试里的固化提醒

- **集成测试文件顶部**应加注释，例如：
  `// 注意：本测试用 mock fetch/Response，不覆盖 Supabase 网关的 Content-Type rewrite 等平台行为；`
  `// UI 类函数部署后须用 agent-browser 真实浏览器验证（见 deploy_verification_checklist）。`
- **commit message** 涉及 UI/HTML 时，标注「✅ 本地测试通过（不覆盖网关行为，部署后已浏览器验证）」。
- **PR / 部署前**自查清单里加一条：「是否命中平台约束预检卡 §1–§2？」
